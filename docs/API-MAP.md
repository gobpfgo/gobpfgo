# API map

<!-- anchors-ok: tools/apimap | a package path, not a citation -->

The exported libbpf symbols at [`4f05fb0`](https://github.com/libbpf/libbpf/commit/4f05fb027a08a8a66d03916cf6a68a91e2c720ea) map to Go identifiers here. The table is generated by `tools/apimap`; this page records the naming contract and the status of each symbol.

## Provenance metadata

Every Go file starts with a provenance block. Ported files use:

<!-- anchors-ok: go | a code-fence language, not a source snippet -->
```go
// libbpf-source: src/libbpf.c
// libbpf-commit: <full sha>
// libbpf-symbols: bpf_object__open_file, bpf_object__open_mem
```

Original files use `// gobpfgo-origin: original`. A reimplementation of a C
module uses both tags. `libbpf-source` may repeat; `libbpf-symbols` is a
comma-separated list. The API map generator reads these tags, and the godocs
describe the Go behavior instead of repeating the C mapping.

## Naming rule

| C | Go |
|---|---|
| `bpf_object__open_file` | `BpfObjectOpenFile` |
| `bpf_object__open_mem` | `BpfObjectOpenMem` |
| `bpf_program__attach_kprobe` | `BpfProgramAttachKprobe` |
| `bpf_map__lookup_elem` | `BpfMapLookupElem` |
| `btf__parse` | `BtfParse` |
| `btf__add_struct` | `BtfAddStruct` |
| `ring_buffer__consume_n` | `RingBufferConsumeN` |
| `user_ring_buffer__reserve_blocking` | `UserRingBufferReserveBlocking` |
| `libbpf_num_possible_cpus` | `LibbpfNumPossibleCpus` |

Split the C name on `__`, CamelCase each segment, and prefix with `Bpf`, `Btf`, `RingBuffer`, `UserRingBuffer` or `Libbpf`. UAPI constants keep their exact spelling.
